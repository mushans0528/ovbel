## 一、网站建设过程中的原始提示词

以下按项目推进顺序整理，尽量保留原始表达。

### 1. 初始建站与扩展性分析

> 我要做一个农机配件贸易公司的网站，后续会持续增加产品页，请帮我分析一下实现方案。

这条提示词确定了最初的核心诉求：网站不是一次性宣传页，而是需要持续扩展产品的 B2B 产品目录和询盘网站。

### 2. 代码托管和部署方式

> 我想把代码托管在 GitHub，网站部署在 Cloudflare。

由此确定技术方向：GitHub 管理版本，Cloudflare Workers/OpenNext 负责网站构建、部署和全球分发。

### 3. 读取旧网站并形成开发文档

> https://hr31395247.jzfkw.net/
> 这是我现有的网站，请读取这个网站内容，整理成可供开发的文档。

核心要求是先审计旧站，再区分：可迁移内容、需要重写内容、缺失内容、错误模板内容和待确认资料。

### 4. 更换网站资料来源

> https://www.respowerbelt.com/
> 改为从这个网站读取信息。

这条提示词将公司、产品和业务资料的主要来源切换为 Respower 官网。

### 5. 调整网站业务定位

> 请将网站主体改为工业机械配件站。

网站由“农机配件优先”调整为“工业机械配件与输送解决方案站”，农业和粮食加工改为应用行业之一。

- 品牌和域名：OVBEL / `ovbel.com`

## 二、从历史提示词提炼出的长期要求

### 1. 网站定位

- OVBEL 是工业机械配件 B2B 产品和询盘网站。
- 核心方向包括输送带、动力传动、输送机组件、橡胶与胶管、矿山配件、电机与驱动设备。
- 农业和粮食加工属于应用行业，不是唯一主体。
- 页面目标是帮助海外客户理解产品、确认工况并发起询盘，而不是直接在线零售。

### 2. 技术和部署

- 代码仓库：`https://github.com/mushans0528/ovbel.git`
- 正式分支：`main`
- 前端：Next.js + TypeScript
- 部署：Cloudflare Workers / OpenNext
- 多语言路径：`/en/`、`/zh/`
- 新功能必须完成构建和 TypeScript 验证。
- 不允许修改代理设置。

### 3. 设计方向

- 工业、专业、可靠、现代，避免廉价模板感。
- 主色为深海军蓝、工业蓝、安全橙、白色和工业灰。
- 参考旧站的信息密度和页面节奏，但不照搬品牌、素材或代码。
- 优先使用真实产品图和工程图；AI 图片只能用于明确的品牌化插图或分享卡，不能冒充真实产品。
- 图片可点击放大，但不在图片上显示放大镜装饰图标。

### 4. 产品页扩展原则

- 产品页必须由统一数据模型驱动，不能为每个产品硬编码一套页面。
- 不同产品可按内容开启或隐藏花纹、型号、应用、储运、参数、图片和询盘模块。
- 新产品上线时，需要同步检查产品列表、分类页、相关产品、询盘预填、搜索、SEO、站点地图和多语言入口。
- 产品事实、编辑性文案和待确认参数必须分开。
- 不能编造价格、认证、温度、强度、库存、评价或未确认技术数据。

### 5. 产品素材原则

- 优先从公司 CMS、旧站、服务器备份或内部图库获取。
- 记录图片来源、产品匹配、权利主体和审核状态。
- 不使用其他供应商的搜索结果图片替代。
- 产品图片需包含主图、细节、应用、尺寸/工程图等角色。
- 使用 WebP/AVIF 优化发布版本，同时保留原始母版。

## 四、推荐的提示词结构

以后提出网站任务时，建议按下面七段组织，能明显减少返工：

```text
【目标】要新增、重做还是检查什么
【仓库】仓库 URL、分支、产品 slug 或页面 URL
【资料】来源网页、文档、Excel、图片或已确认事实
【设计】参考风格、品牌色、需要保留或避免的元素
【功能】多语言、图库、参数、询盘、搜索、SEO、交互
【验收】桌面/移动端、构建、类型、测试、无障碍
【交付】更新文档、commit、push，以及报告提交哈希
```
